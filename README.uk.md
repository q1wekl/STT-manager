# SFX RTX TripleX

## Про проєкт

Застосунок з JNI-обгорткою над whisper.cpp для розпізнавання мовлення, з підтримкою прискорення через NVIDIA CUDA або Vulkan. Написаний з використанням JavaFX (Liberica JDK).

## Структура assets, які НЕ зберігаються в git

Важкі файли (моделі, нативні бібліотеки) не зберігаються в самому репозиторії, а розповсюджуються через **GitHub Releases**. Причина: git погано працює з великими бінарними файлами — репозиторій роздувається до гігабайтів і стає незручним для клонування.

Замість цього, після клонування репозиторію треба один раз запустити скрипт, який довантажить усе необхідне.

### Що саме довантажується

| Що | Звідки | Куди розпаковується |
|---|---|---|
| Whisper-моделі (`.bin`) | Release з тегом `models` | `Dyplom/models/whisper/` |
| Нативні бібліотеки CUDA | `native-cuda.zip` з Release `native` | `Dyplom/native/cuda/` |
| Нативні бібліотеки Vulkan | `native-vulkan.zip` з Release `native` | `Dyplom/native/vulkan/` |

Посилання на всі релізи: https://github.com/q1wekl/SFX-RTX-TripleX/releases

### Моделі (`models`)

Файли формату GGML для whisper.cpp, різних розмірів (більший файл = точніше розпізнавання, але повільніше і важче):

- `ggml-tiny.bin` — найменша, найшвидша
- `ggml-base.bin`
- `ggml-small.bin`
- `ggml-medium.bin`
- `ggml-large.bin`
- `ggml-large-v3.bin` — найбільша, найточніша

### Нативні бібліотеки (`native`)

Тут два архіви, бо CUDA-версія і Vulkan-версія бібліотек **несумісні між собою** (це різні збірки whisper.cpp під різне залізо), тому вони не можуть лежати в одному спільному наборі файлів — довелось розділити на архіви:

- `native-cuda.zip` — для запуску з прискоренням на відеокартах NVIDIA
- `native-vulkan.zip` — для запуску через Vulkan (універсальніше, працює на різних GPU)

Обидва архіви містять:
- `ggml.dll`, `whisper.dll`, `whisper-jni.dll` — самі бібліотеки whisper.cpp (різні для CUDA/Vulkan)
- `msvcp140.dll`, `vcruntime140.dll` — стандартні Visual C++ runtime бібліотеки (однакові в обох архівах)

Плюс:
- `native-cuda.zip` додатково містить `cublasLt64_12.dll`, `cublas64_12.dll` (CUDA-специфічні)
- `native-vulkan.zip` додатково містить `glslangd.dll` (Vulkan-специфічна)

## Як налаштувати проєкт після клонування

### 1. Встанови Liberica JDK (з JavaFX)

Проєкт використовує Liberica JDK Full (там вже вбудований JavaFX, окремо ставити не треба).

Завантажити: https://bell-sw.com/pages/downloads/

Після встановлення налаштуй `JAVA_HOME` на шлях до встановленої Liberica.

> Liberica JDK **не зберігається в git** — це інструмент збірки, кожен розробник ставить його сам локально, як і будь-яку IDE чи компілятор.

### 2. Довантаж моделі та нативні бібліотеки

Запусти скрипт `scripts/download-assets.sh` (детальний опис — нижче) з кореня репозиторію:

```bash
bash scripts/download-assets.sh
```

За замовчуванням скрипт качає CUDA-варіант нативних бібліотек. Якщо в тебе відеокарта не NVIDIA або хочеш Vulkan-варіант — постав змінну `VARIANT=vulkan` перед запуском:

```bash
VARIANT=vulkan bash scripts/download-assets.sh
```

### 3. Збери проєкт

(тут за потреби додай свою команду збірки — Gradle/Maven/CMake, залежно від того, що використовується)

## Що робить `scripts/download-assets.sh` (пояснення по рядках)

Скрипт — це bash-файл, який виконує послідовність команд `curl` (завантаження файлу за посиланням) та `unzip` (розпакування архіву). Логіка така:

1. **Створює папки**, куди підуть файли (`mkdir -p`) — якщо папка вже є, нічого не ламає.
2. **Перебирає список моделей** у циклі `for` і для кожної викачує окремий `.bin` файл з Release `models` за прямим посиланням виду:
   ```
   https://github.com/q1wekl/SFX-RTX-TripleX/releases/download/models/ggml-tiny.bin
   ```
3. **Завантажує архів** нативних бібліотек (`native-cuda.zip` або `native-vulkan.zip`, залежно від `VARIANT`), розпаковує його (`unzip`) у відповідну папку і видаляє сам архів (`rm`), щоб не займав місце.

Скрипт можна запускати повторно скільки завгодно — він просто перезапише файли новими копіями, нічого не зламає.

## Примітка про історію git

Якщо клонуєш репозиторій з нуля — усе працює прозоро, важких файлів там немає взагалі, клонування швидке. Стара версія репозиторію (до чистки) містила ці файли прямо в git-історії, через що розмір доходив до ~8 ГБ — це було виправлено через `git filter-repo`.
